# 本実装の検証記録

2026-09-13、macOS arm64、Node.js 24.14.1。`npm run build`とNode標準テスト全9件が成功。独立Final reviewの指摘は修正・再確認済み。フォーム操作の修正についても3つの観点でPlan・Final reviewを完了し、未解決の指摘はない。

## 確認した流れ

1. [公開されているタブUI](https://ui.shadcn.com/docs/components/base/tabs)の対象部分を撮影し、独自のReact実装・日本語のサンプル文章として登録。
2. このリポジトリの既存サインイン画面のスクショを原本にし、独立したReact実装として登録。ユーザー提供・外部サイト由来の画像とは扱わない。
3. 元の作業フォルダを削除した状態で、別ディレクトリに起動した実MCPクライアントから取得。この時点では検証用Web・ブラウザは停止中。
4. TSX、CSS、原画像、manifestをbase64で分割取得し、SHA-256を照合。別プロジェクトの入口からビルドして描画。
5. 部品のキーボード操作、画面の入力操作、モバイル表示、移植先の見出しのスタイル維持を確認。
6. 実DBに接続したWebで、一覧・詳細・参照画像・コード・モバイル・iframe内Escape・フォーカス復帰を確認。

本番保存先にも既存6サンプルと上記2件を登録し、`collection doctor`は8件・問題なし。元画像と生成サムネイルは別ファイルで保持している。

撮影用Chromiumの未導入、バックアップのWAL関連ファイル残存、実ブラウザでの長いIDの折り返しを検証中に確認し、導入手順・保存処理・表示を修正した。

Final reviewでは、閲覧iframe自身のHTTP遷移と親CLIの強制終了後のworker残存を指摘された。前者は実listenerへの到達1件、後者は親終了後のプロセス残存を修正前に再現した。親画面にも`frame-src 'none'`を設定し、workerにも期限とIPC切断時の終了処理を追加。修正後はlistener到達0、worker・ブラウザとも残存0を確認した。仕様の確認には[W3C CSP](https://www.w3.org/TR/CSP/)と[NodeのIPC切断イベント](https://nodejs.org/api/process.html#event-disconnect)を参照した。

最後の実画面確認で、`allow-forms`なしのsandboxがフォームの入力確認まで無効にする点を発見した。初期状態にも一致する「デモ」というassertを、送信後固有の「入力を確認しました」へ変更し、修正前の失敗を再現。閲覧・撮影双方に`allow-forms`を追加し、`allow-same-origin`は引き続き不許可とした。空・不正メールを拒否し、有効メールでは状態が切り替わることを確認した。実送信はCSPの`form-action 'none'`で遮断し、ネイティブPOSTのCSP違反を待って実listener到達0を確認した。フォーム修正は新しい3セッションでPlanとFinalを行い、各段階は同じ会話を保持して確認を完了した。

Project Memoryは既存の[収集と再利用の分離](project-memory/records/20260913-051200-separate-collection-and-reuse.md)を、実装場所・独立MCP・保存方式の判断根拠として参照した。完了前にcapture候補を評価し、追加の記録は作成していない。既存判断の適用と、コード・本記録から理由を復元できる実装判断に収まるため。

## メモリ

`tests/workflow.test.ts`が同一実行で`ps`のRSSを計測。2026-09-13の代表実測。Webは開発サーバーではなくビルド済み配信。ブラウザには同じ検証中の移植確認ページの履歴も含む。ブラウザの共有メモリが重複集計される可能性があるため、PC全体の増加量とは異なる。

| 状態 | プロセス数 | RSS |
| --- | ---: | ---: |
| 対象アプリ・MCP停止 | 0 | 0 MiB |
| MCP接続待機 | 1 | 94.3 MiB |
| MCP検索20回とソース・素材取得後 | 1 | 99.8 MiB |
| Web一覧（サーバー） | 1 | 86.5 MiB |
| Web一覧（ブラウザ一式） | 4 | 375.5 MiB |
| 詳細1件（サーバー／ブラウザ） | 1 / 4 | 88.8 / 432.1 MiB |
| 詳細を閉じた後（サーバー／ブラウザ） | 1 / 4 | 64.9 / 401.3 MiB |
| 検証用MCP・Web・ブラウザ終了後 | 0 | 0 MiB |

MCPの検索・取得ではビルドやブラウザは起動しない。Web一覧はiframe 0、詳細は1、閉じる／タブ変更後は0。プロセス終了と、GCによりRSSがすぐ戻ることは区別する。メモリの許容上限はまだ設定していない。大規模コレクションの長期運用値ではない。

最新の生データは`artifacts/memory.json`、画面は`artifacts/collection-*.png`と`artifacts/transplant-*.png`。これらはテストの生成物でGit管理外。

## 適用範囲と未実施

- 個人のローカル環境向け。macOS/Chromiumで検証した。Windowsのプロセス終了・計測には未対応。
- 日常利用するMCPクライアントの設定は変更していない。接続用JSONの表示コマンドを用意し、実SDKクライアントで接続を検証した。
- 保存内容の編集・削除・同期・履歴管理、アプリ内AI生成は今回の対象外。
- 名前からIDを生成しない。既存項目の名前編集は未提供であり、変更したパッケージの再登録は別UIになる。
- 到達できないURLの取り扱いは登録手順に記載。ログイン情報の預かりや自動クロールは実装しない。
