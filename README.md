# Formshelf

気に入ったUIを動くコードとして集め、次の開発で再利用するための、個人用UIコレクションのモックです。

## 起動

Node.js 22.12以降（開発・検証環境: Node.js 24）を使います。

```sh
npm install
npm run dev
```

表示されたローカルURLを開きます。通常は <http://127.0.0.1:5173> です。終了はターミナルで `Ctrl+C`。

```sh
npm run build   # TypeScriptの型検査と本番ビルド
npm run preview # ビルド済みの画面をローカルで確認
```

## このモックで試せること

- 6件のオリジナルサンプルを、静止サムネイルから選択。
- 名前・タグ・IDの検索、カテゴリと部品／画面全体の絞り込み、並び替え。
- 詳細内の操作可能なプレビュー、デスクトップ／モバイル幅の切り替え。
- 参照画像、実際のTSXとCSS、説明、IDの確認とコピー。
- スクショやURLをエージェントへ渡して追加する運用の案内。

サンプルは料金の切り替え、コマンド検索、集計期間の変更、フォーム検証、メニュー開閉、ボタンの状態変化に対応します。メール送信、決済、認証などの外部処理は行いません。操作状態はプレビューを閉じるとリセットします。

## 今回の範囲と後続実装

今回は画面と操作の確認用です。SQLite保存、MCPサーバー、自動収集・登録、ファイルのアップロード、URL取得は未実装です。UIに表示する参照画像は、自作サンプルの初期状態を撮影したもので、外部サイトの収集実績ではありません。

合意した後続構成:

- 収集・新規実装は、このコレクションのプロジェクトで外部エージェントに依頼する。
- 入力はスクショまたはURL。URLだけなら対象部分を確認し、閲覧できない場合はスクショ／録画へ切り替える。
- UIのメタデータはSQLite、コードと画像はファイルに保存する。
- 別プロジェクトからは検索・取得専用MCPで完成済みUIを取り出し、移植する。
- MCPはWebアプリに依存しない。Webアプリは見た目や動きの確認時だけ起動する。

## ソースの構成

- `src/App.tsx`: 一覧、検索、絞り込み、追加方法の案内。
- `src/catalog.ts`: 固定ID、説明、タグ、サンプルとソースへの参照。
- `src/Detail.tsx`: プレビュー、参照画像、コード表示とコピー。
- `src/Preview.tsx`: `/?preview=UI-001` 形式のプレビュー入口。
- `src/samples/`: 個別のReact実装と共有のサンプルCSS。
- `public/thumbnails/`: サンプル初期状態の静止画像。

一覧ではiframeを生成しません。詳細で選択中の1件だけを遅延読込し、詳細を閉じる／参照画像・コードへ切り替えるとプレビューを破棄します。ソース本文はコード表示時だけ読み込みます。

iframeは**固定の信頼済みサンプルの表示とCSSの分離**に使っています。未信頼HTMLや任意の取得コードを安全に実行するためのサンドボックスではありません。外部コードを取り込む段階で実行境界を別途設計します。

サンプルを直接移植する場合は、該当TSXと`src/samples/samples.css`を同じフォルダに置き、React環境からコンポーネントをimportします。初期モックではサンプル用CSSを共有しているため、移植先に合わせて必要部分を整理してください。

## 検証

`npm run build`に加え、実ブラウザで検索・複合絞り込み・空状態・並び替え・全サンプルの操作・参照画像・コード/CSS表示・IDコピーを確認しています。デスクトップと390pxの画面、320pxのサンプルと詳細、iframe内からEscapeで閉じたあとのフォーカス復帰も確認しています。

既存テスト基盤はありません。永続データ変更・外部APIを含まないモックのため、新しいテストフレームワークは追加せず、ブラウザの操作とassertで外部挙動を確認しました。SQLite/MCPなどの永続化・公開APIを実装する段階で、対応する契約の自動テストを追加します。

詳細は [検証記録](docs/mock-verification.md) を参照してください。
